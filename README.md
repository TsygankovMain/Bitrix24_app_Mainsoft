# Учёт трудозатрат для Bitrix24

Приложение для Bitrix24, которое позволяет учитывать рабочее время прямо в задачах, хранить записи в смарт-процессе CRM и строить управленческие отчеты по сотрудникам, проектам и качеству учета времени.

Репозиторий содержит актуальную рабочую версию приложения на связке `Nuxt 3 + Django + PostgreSQL`.

## Что умеет приложение

- учет времени внутри карточки задачи Bitrix24;
- разделение часов на учитываемые и неучитываемые;
- редактирование, удаление и разделение записи времени;
- аналитические отчеты с фильтрами по периоду, сотрудникам и проектам;
- выгрузка отчетов и исходных данных в Excel;
- настройка смарт-процесса и маппинга полей из интерфейса приложения;
- просмотр локального кэша синхронизированных записей и ручная синхронизация с Bitrix24.

## Основные разделы интерфейса

### Работа в задаче

Во вкладке приложения в задаче пользователь может:

- добавить запись времени по конкретной задаче;
- изменить существующую запись;
- разделить запись на две части;
- удалить запись;
- видеть сумму учитываемых часов и расчет по ставке часа.

### Отчеты

Сейчас в приложении доступны следующие отчеты:

1. `Отчет по сотрудникам`
2. `Отчет по проектам`
3. `Ежедневная нагрузка`
4. `Учет по проектам и задачам`
5. `Потери выручки`
6. `Дисциплина внесения времени`
7. `Фокус и распыление`

Во всех основных отчетах используется единый сценарий: выбрать фильтры, нажать `Сформировать`, при необходимости выгрузить результат через `Скачать Excel`.

### Настройки

В разделе настроек доступны:

- `Настройка полей (Маппинг)` для выбора или создания смарт-процесса и сопоставления полей;
- `Сырые данные (БД)` для просмотра локального кэша и динамической выгрузки Excel;
- настройка кликабельных меток в отчетах;
- панель отладки.

## Как устроены данные

Приложение работает в двух контурах:

- в карточке задачи данные читаются и записываются напрямую через Bitrix24 JSSDK;
- в отчетах используется backend на Django, который синхронизирует записи из Bitrix24 в локальную PostgreSQL и строит агрегаты по локальному кэшу.

Основная сущность локальной базы:

- `TimesheetItem` — запись времени, синхронизированная из смарт-процесса Bitrix24;
- `Bitrix24Account` — учетные данные установленного приложения;
- `RequestLog` и `SystemLog` — сервисные журналы для диагностики.

## Стек

- Frontend: `Nuxt 3`, `Vue 3`, `TypeScript`, `Pinia`, `@bitrix24/b24ui-nuxt`
- Backend: `Django`, `b24pysdk`
- Database: `PostgreSQL`
- Export: `xlsx`
- Infra: `Docker`, `docker compose`

## Локальный запуск

### Требования

- Docker и `docker compose`
- доступ к порталу Bitrix24, где можно установить локальное приложение
- заполненный `.env`

### Быстрый старт

1. Скопируйте переменные окружения:

```bash
cp .env.example .env
```

2. Проверьте основные значения в `.env`:

- `CLIENT_ID`
- `CLIENT_SECRET`
- `VIRTUAL_HOST`
- `DB_NAME`
- `DB_USER`
- `DB_PASSWORD`
- `JWT_SECRET`

3. Запустите локальную среду:

```bash
make dev-python
```

4. Зарегистрируйте приложение в Bitrix24:

- URL приложения: `https://ваш-домен/`
- URL установки: `https://ваш-домен/install`

5. После установки откройте в приложении:

- `Настройки -> Настройка полей (Маппинг)`
- выберите или создайте смарт-процесс;
- создайте поля;
- сохраните конфигурацию.

После этого можно открывать вкладку приложения в задачах и пользоваться отчетами.

## Основные команды

```bash
make dev-python    # локальная разработка на Python backend
make down          # остановить контейнеры
make logs          # посмотреть логи
make queue-up      # поднять RabbitMQ отдельно
make queue-down    # остановить RabbitMQ
```

## Что важно учитывать

- отчеты строятся по локальному кэшу backend, а не напрямую по live-данным Bitrix24;
- встраиваемая страница задачи должна открываться именно внутри Bitrix24;
- маппинг полей обязателен: без него приложение не сможет корректно читать и сохранять записи времени;
- ставка часа настраивается в маппинге и используется в расчетах внутри приложения.

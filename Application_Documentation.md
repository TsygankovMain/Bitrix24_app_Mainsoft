# Документация продукта

## Что делает приложение

«Учёт трудозатрат» — встроенное Bitrix24-приложение для команд, которым нужен не просто ввод часов, а управленческий контур:

- сотрудники фиксируют время прямо в задаче;
- записи сохраняются в CRM смарт-процессе;
- руководители получают отчеты по проектам, сотрудникам и качеству учета;
- администратор управляет маппингом и проектной конфигурацией из интерфейса.

## Основные роли

| Роль | Что получает |
|---|---|
| Сотрудник | быстрый ввод времени в задаче |
| Руководитель проекта | видимость по трудозатратам и загрузке |
| Руководитель направления | аналитику по эффективности и дисциплине |
| Администратор | настройку СП, маппинга и диагностики |

## Основные пользовательские сценарии

### 1. Работа в задаче

Пользователь:

- открывает вкладку приложения в задаче;
- добавляет или редактирует запись времени;
- при необходимости делит запись;
- видит итог по часам и стоимости.

### 2. Работа с проектами

Пользователь:

- открывает проектный контур;
- просматривает board/timeline;
- открывает карточку проекта;
- переходит в проектный отчет.

### 3. Работа с отчетами

Пользователь:

- выбирает период;
- при необходимости задает сотрудников и проекты;
- нажимает `Сформировать`;
- анализирует результат или выгружает Excel.

### 4. Настройка приложения

Администратор:

- создает или выбирает смарт-процессы;
- подгружает поля;
- выполняет маппинг;
- задает ставку часа;
- использует отладку и сырые данные.

## Набор отчетов

В текущей версии доступны:

1. Отчет по сотрудникам
2. Отчет по проектам
3. Ежедневная нагрузка
4. Учет по проектам и задачам
5. Потери выручки
6. Дисциплина внесения времени
7. Фокус и распыление

## Как устроены данные

Рабочая схема:

1. сотрудник вносит запись внутри задачи;
2. запись сохраняется в смарт-процессе Bitrix24;
3. backend синхронизирует записи в локальную PostgreSQL;
4. отчеты строятся уже по локальному кэшу.

Это нужно для стабильной аналитики, фильтров, Excel-выгрузок и project/report logic.

## Что важно для внедрения

- без корректного маппинга приложение не будет работать полноценно;
- проектная аналитика зависит от project SPA и связки полей;
- production должен работать на собственном домене приложения, без CloudPub;
- после смены production-домена placement’ы Bitrix24 нужно перевязать.

## 1. Обзор продукта

### Что это такое?

**«Учёт трудозатрат»** — это встроенное приложение для Битрикс24, которое позволяет командам фиксировать рабочее время прямо внутри задач, а руководителям — видеть полную аналитику трудозатрат по сотрудникам, проектам и задачам.

Приложение работает как «надстройка» поверх Битрикс24 CRM (Смарт-процессов), не требует внешних сервисов и хранит все данные в вашей инфраструктуре.

### Для кого?

| Роль | Ценность |
|------|----------|
| **Сотрудник** | Быстро фиксирует время, не выходя из задачи. Не нужно заполнять сторонние таблицы |
| **Руководитель проекта** | Контролирует загрузку команды и видит реальный прогресс в часах по каждой задаче |
| **Финансовый директор / бухгалтер** | Получает отчёты для биллинга клиентов и анализа себестоимости проектов |
| **HR** | Отслеживает занятость сотрудников, формирует табели |

### Ключевые принципы

- **Нативная интеграция** — работает прямо в карточке задачи Битрикс24, без переключения контекста
- **Гибкость** — хранит данные в Смарт-процессах CRM, которые администратор настраивает под себя
- **Два режима учёта** — «Учитываемые» (billable) и «неучитываемые» (non-billable) часы для точного биллинга

## 2. Архитектура приложения

Приложение состоит из трёх взаимодействующих частей:

```
Битрикс24 (iframe)
       │
       ▼
  Frontend (Nuxt 3 / Vue 3)
  ├── Встройка в задачи (embedded)
  ├── Отчёты (4 типа)
  ├── Настройки (маппинг полей)
  └── Руководство пользователя (guide)
       │
       ▼
  Backend (Django / Python)
  ├── REST API (JWT-аутентификация)
  ├── Синхронизация данных из Битрикс24
  └── Генерация отчётов и Excel-экспорт
       │
       ▼
  База данных (PostgreSQL)
  └── Локальный кэш записей (TimesheetItem)
```

## 3. Основные модули

### 3.1. Модуль: Встройка в задачи (`/embedded`)

Это главный пользовательский интерфейс, открывающийся прямо в карточке задачи Битрикс24.

#### Что видит пользователь?

**Дерево задач** — рекурсивная иерархия от открытой задачи вниз по всем подзадачам. Для каждого узла дерева отображается:
- Название задачи
- Суммарные фактические часы (учитываемые и неучитываемые)
- Кнопка **«+ Отразить»** — добавить запись времени

**Панель сводки (Header):**
- Кнопка «Отразить» (глобальная — для корневой задачи)
- Поле «Стоимость часа» — настраиваемая ставка (руб./час)
- «Сумма для клиента» — автоматически рассчитывается: учитываемые часы × ставка

#### Как работает добавление времени?

1. Пользователь нажимает **«+ Отразить»** рядом с нужной задачей
2. Открывается форма с полями:
   - **Описание** (текстовое). Что было сделано?
   - **Часы** (число). Например: `1.5`
   - **Дата** (по умолчанию — сегодня, можно изменить)
   - **Сотрудник** (список активных пользователей портала)
   - **Учитывать?** (флаг — billable/non-billable)
3. При сохранении:
   - Запись создаётся в Битрикс24 Смарт-процессе через `crm.item.add`
   - Автоматически заполняются поля иерархии задач (ID и названия родительских задач)
   - Автоматически заполняются ID проекта, название проекта, ИНН компании и клиента (из задачи)
4. Дерево задач обновляется — новые часы отображаются на всех уровнях иерархии

#### Редактирование записи

Клик по существующей записи в дереве открывает ту же форму в режиме редактирования. Доступны:
- Изменение всех полей
- Удаление записи (с подтверждением)
- **Разделение (Split)**

#### Функция Split (разделение записи)

Позволяет разбить одну запись о времени на две. Сценарий использования: потратили 5 часов, из которых 3 — оплачиваемая работа, 2 — внутренние обсуждения.

**Как работает:**
1. В нижней части формы редактирования находится блок «Разделение (Split)»
2. Пользователь вводит количество часов, которое нужно «откусить» от текущей записи
3. Опционально: поставить флаг, чтобы новая запись имела противоположный тип учёта (billable ↔ non-billable)
4. Результат: исходная запись уменьшается, появляется новая запись с указанными часами

#### Руководство пользователя (Help)

Кнопка «Справка» в заголовке открывает панель с пользовательским гайдом:
- В десктопной Битрикс24 — открывает нативный слайдер (`BX24.openApplication`)
- Fallback: телепортируемый компонент поверх интерфейса

### 3.2. Модуль: Отчёты

Основной аналитический раздел приложения. Доступен из главного меню (главная страница). Все отчёты работают с данными из локальной БД (синхронизированными с Битрикс24).

#### Общие фильтры (для всех отчётов)
- **Дата отражения: с/по** — диапазон дат
- **Сотрудники** — мультивыбор из списка (динамический)
- **Проекты** — мультивыбор из списка (динамический)

---

#### Отчёт 1: По сотрудникам и проектам (`/reports/employee`)

**Цель:** Понять, кто сколько работал и над чем.

**Группировка данных:**
```
Сотрудник
  └── Проект
        └── Иерархия задач (дерево)
              └── Метки времени (конечные записи)
```

**Столбцы таблицы:**
| Поле | Описание |
|------|----------|
| Название задачи / Метка | Имя задачи или описание записи |
| ID задачи | Идентификатор в Битрикс24 |
| Часы | Количество затраченных часов |
| Тип | Учитываемые / Неучитываемые |
| Дата | Дата отражения |

**Свёртка:** Все группы можно сворачивать/разворачивать. По умолчанию свёрнуты.

---

#### Отчёт 2: По проектам и сотрудникам (`/reports/project`)

**Цель:** Понять, куда уходят ресурсы в разрезе проектов.

**Группировка данных:**
```
Проект
  └── Сотрудник
        └── Иерархия задач (дерево)
              └── Метки времени
```

Столбцы идентичны Отчёту №1. Если над задачей работали несколько сотрудников, каждый отображается в своей ветке под проектом.

---

#### Отчёт 3: Ежемесячный табель (`/reports/daily`)

**Цель:** Классический «табель» — контроль ежедневного присутствия и занятости.

**Структура:** Матрица (сетка):
- **Строки:** Сотрудники
- **Столбцы:** Дни месяца (1–31) + итоги (Всего, Учтено, Не учтено)

**Дополнительные функции:**
- В ячейке с часами за день — клик открывает **popup-детализацию**: список всех задач и записей за этот день
- Выходные дни визуально выделяются
- По умолчанию показывается текущий месяц

---

#### Отчёт 4: По проектам/задачам (`/reports/project-task`)

**Цель:** Детальная разбивка до уровня конкретной задачи и исполнителя.

**Группировка данных:**
```
Проект
  └── Задача (иерархия в виде дерева)
        └── Сотрудник
              └── Метки времени
```

**Особенности:**
- Самый детальный из всех отчётов
- Все группы свёрнуты по умолчанию
- Клик на кликабельную метку → открывает карточку элемента в Битрикс24 (если включена опция в настройках)
- **Экспорт в Excel** (кнопка в шапке) — вся текущая выборка выгружается в `.xlsx`

### 3.3. Модуль: Сырые данные (`/reports/raw-data`)

Технический раздел для работы с данными на низком уровне. Доступен из раздела «Настройки».

#### Блок: Синхронизация и просмотр локальной БД

- **Кнопка «Синхронизировать с Б24»:** запускает выгрузку всех элементов из Смарт-процесса Битрикс24 в локальную PostgreSQL. Отображает количество синхронизированных записей.
- **Таблица кэша:** показывает все записи локальной БД с полями:
  - ID (Битрикс), ID задачи, ID сотрудника, Проект, Иерархия задач, Часы, Неучт. Часы, Учитывать?, Описание, Дата создания
- **Фильтрация по дате создания записи** с кнопками «Применить» / «Сбросить»
- **Пагинация:** по 50 записей на страницу

#### Блок: Динамическая выгрузка в Excel

Позволяет скачать данные напрямую из Битрикс24 (минуя локальный кэш) с гибкой настройкой:

| Настройка | Описание |
|-----------|----------|
| **Тип даты** | По дате отражения (`data`) или по дате создания (`createdTime`) |
| **Период: с/по** | Фильтр по дате |
| **Поля для экспорта** | Чекбокс-список всех полей Смарт-процесса. «Выбрать все» / «Снять все» |

**Результат:** Скачивается файл `raw_data_export_ДАТА_ДАТА.xlsx` с заголовками из Битрикс24.

#### Страница маппинга (`/settings/mapping`)

Ключевая страница первоначальной настройки и переконфигурации.

**Шаг 1: Выбор Смарт-процесса**

Выпадающий список всех имеющихся Смарт-процессов на портале. Пользователь выбирает тот, в котором будут/есть поля учёта времени.

Опционально: указать **«Стоимость часа по умолчанию»** (руб.) — используется для расчётов в встройке задачи.

**Шаг 2: Создание (для новых инсталляций)**

| Кнопка | Действие |
|--------|----------|
| **«Создать смарт-процесс»** | Автоматически создаёт новый Смарт-процесс «Метки времени» через `crm.type.add` |
| **«Создать все поля»** | Автоматически создаёт 14 полей в выбранном процессе (через прямые вызовы `userfieldconfig.add` из JS SDK) |
| **«Подгрузить поля»** | Загружает список полей выбранного процесса (для ручного маппинга) |

**Шаг 3: Таблица маппинга** — сопоставление 14-и полей приложения с реальными полями выбранного Смарт-процесса:

| Поле приложения | Тип | Назначение |
|-----------------|-----|-----------|
| ID Задачи | integer | Связь с задачей Б24 |
| Сотрудник | employee | Кто списал время |
| Количество часов | double | Объём работы |
| Учитываем? | boolean | Billable-флаг |
| Неучитываемые часы | double | Non-billable часы |
| Описание | string | Комментарий |
| Название Проекта | string | Имя проекта/группы |
| ID Проекта | integer | ID группы задач |
| Дата | date | Дата отражения |
| Иерархия ID | string (JSON) | Массив ID родительских задач |
| Иерархия Названий | string (JSON) | Массив имён родительских задач |
| Название задачи | string | Имя конечной задачи |
| Наш ИНН | string | Реквизиты вашей компании |
| ИНН клиента | string | Реквизиты клиента |

После настройки — кнопка **«Сохранить»** возвращает на главную страницу настроек.

## 5. Процесс синхронизации данных

**Ручная синхронизация** (кнопка «Синхронизировать с Б24»):

1. Вызывается метод `crm.item.list` для выбранного Смарт-процесса (`sp_entity_type_id`)
2. Данные загружаются пакетами по 50 записей с пагинацией
3. Каждая запись нормализуется через `TimesheetSyncService`:
   - Разворачиваются JSON-поля иерархии
   - Вычисляются учитываемые/неучитываемые часы
4. Записи создаются или обновляются в PostgreSQL (`upsert` по `bitrix24_account` + `bitrix_id`)
5. Возвращается количество синхронизированных записей

---

## 6. Аутентификация

**Схема работы:**
1. Фронтенд получает `auth_data` от Битрикс24 SDK при загрузке
2. Отправляет POST `/api/getToken` с токенами Б24 → бэкенд валидирует, создаёт/обновляет `Bitrix24Account` и возвращает JWT
3. JWT (срок действия: 60 минут) хранится в памяти Pinia-store
4. Все API-запросы к бэкенду идут с заголовком `Authorization: Bearer <jwt>`
5. JWT автоматически обновляется при необходимости через `reinitToken()`

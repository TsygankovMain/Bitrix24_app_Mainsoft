# Инструкция по деплою в Timeweb Cloud Apps

## 1. Настройка приложения

При создании приложения в Timeweb Cloud Apps выберите:
*   **Тип**: Docker
*   **Порт**: 8000 (укажите это в настройках порта приложения)
*   **Регион**: По вашему выбору (RU/PL и т.д.)

## 2. Переменные окружения (Environment Variables)

В разделе "Переменные" добавьте следующие ключи и значения (значения возьмите из вашего локального `.env` или сгенерируйте новые):

| Ключ | Описание | Пример значения |
| :--- | :--- | :--- |
| `DB_NAME` | Имя базы данных | `appdb` |
| `DB_USER` | Пользователь БД | `appuser` |
| `DB_PASSWORD` | Пароль БД | `secure_password` |
| `DB_HOST` | Хост БД | `hostname.timeweb.cloud` (адрес вашей managed базы) |
| `DB_PORT` | Порт БД | `5432` |
| `SECRET_KEY` | Секретный ключ Django | `django-insecure-...` (сгенерируйте сложный ключ) |
| `VIRTUAL_HOST` | Домен вашего приложения | `myapp.twc1.net` (или ваш домен) |
| `DJANGO_SETTINGS_MODULE` | Модуль настроек | `settings` |

> **Важно**: Убедитесь, что для базы данных вы используете или Managed Database от Timeweb, или другую доступную БД. Если вы используете `DB_HOST=database` (как в docker-compose), это не сработает без настройки внутренней сети или использования Docker Compose деплоя (Apps обычно деплоит один контейнер или требует `docker-compose.yml` в корне). В данном случае мы готовим Dockerfile для одиночного контейнера, поэтому БД должна быть внешней.

## 3. Проверка сборки (Локально)

Перед деплоем проверьте, что образ собирается корректно:

```bash
# 1. Сборка
docker build -t app-test .

# 2. Запуск (потребуется файл .env с реальными доступами к БД для полной проверки,
# или можно запустить без переменных, чтобы просто проверить старт uvicorn)
docker run -p 8000:8000 app-test
```

Если контейнер запустился и не упал сразу — uvicorn работает.

## 4. Команды после деплоя (Миграции)

Так как это Django, после деплоя нужно применить миграции. В Timeweb Apps это можно сделать через Shell (консоль) или добавив команду в `CMD` (менее рекомендуется для продакшена, но допустимо).

**Вариант А (Shell):**
Зайдите в консоль приложения и выполните:
```bash
python manage.py migrate
python manage.py createsuperuser
```

**Вариант Б (Автоматически при старте):**
Можно изменить CMD в Dockerfile на:
```dockerfile
CMD ["sh", "-c", "python manage.py migrate && uvicorn asgi:application --host 0.0.0.0 --port 8000"]
```
(Текущий Dockerfile просто запускает сервер).

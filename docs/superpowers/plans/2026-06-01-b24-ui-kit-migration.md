# План спринтов: миграция на Bitrix24 UI Kit

> **Для исполнителей-агентов:** ОБЯЗАТЕЛЬНАЯ СУБ-СКИЛЛ при реализации каждого спринта — `superpowers:subagent-driven-development` (свежий субагент на задачу + двухэтапное ревью). Шаги отмечены чекбоксами `- [ ]`.

**Goal:** Перевести фронтенд на нативный вид Bitrix24 UI Kit (вариант D из оценки) **без поломки функционала**, итеративно и обратимо.

**Architecture:** 6 спринтов от безопасного к рискованному. Сначала «фундамент» (токены/каркас — обратимо одним-двумя файлами), потом листовые компоненты/формы, и в КОНЦЕ — самые рискованные: рекурсивные таблицы отчётов (УТП) и `embedded.vue`. Каждый спринт самодостаточен, тестируется смоук-чек-листом, откатывается `git revert`.

**Tech Stack:** Nuxt 4, Vue 3, `@bitrix24/b24ui-nuxt` 2.5.3 (зафиксировать), Tailwind v4, `reka-ui`, `@tanstack/vue-table`. Бренд `ms-*` (42 класса) → нативные токены Air.

**Связанная оценка:** [../../architecture/ui-kit-migration-assessment.md](../../architecture/ui-kit-migration-assessment.md).

---

## Сквозные правила (для ВСЕХ спринтов)

1. **Обратимость = единица спринта.** Каждый спринт — отдельная ветка от `prod_2026` (`git switch -c ui-sprintN`) ИЛИ серия коммитов с явной точкой отката. Внутри — коммит на каждый файл/компонент (гранулярный откат).
2. **Гейт «ничего не упало»** в конце каждого спринта (см. §Смоук-чек-лист). Прошло → merge в `prod_2026` + push. Не прошло и не чинится быстро → `git revert`/`reset` спринта, разбор бага, повтор.
3. **`embedded.vue` и рекурсивные таблицы отчётов — НЕ трогать** до их выделенных спринтов (S4, S5).
4. **Распределение моделей:** механические замены по шаблону (класс→компонент, удаление мёртвого CSS, повтор паттерна по страницам) — **Haiku**; интеграции/логика/риск (токены, `useOverlay`/`useToast`, рекурсивные таблицы, embedded, ревью) — **Sonnet**.
5. Ничего не выпиливать из `ms-*`, пока класс где-то используется (`grep` перед удалением).

## Смоук-чек-лист (гейт после каждого спринта)

- [ ] `cd frontend && npx nuxt prepare` — без ошибок типов.
- [ ] `npm run lint` — зелёный; `npx tsx --test tests/progress.test.ts` — PASS.
- [ ] Открыть каждый экран (в реальном iframe Bitrix, не только локально): **главная**, **доска проектов** (канбан + drawer карточки), **все 7 отчётов** (Сформировать → данные на месте), **«Сырые данные»** (выгрузка + дозаполнение ИНН), **настройки**, **embedded-отражение** (открыть в задаче).
- [ ] **Особо (УТП):** в «Учёт по проектам/задачам» — иерархия строится, раскрытие/сворачивание работает, кликабельные метки работают, KPI-карточки верны, **Excel-выгрузка открывается и структура сохранена**.
- [ ] **Особо (embedded):** отражение времени создаёт метку, **ИНН проставляется**, иерархия/разделение работают.
- [ ] Сверить со скриншотами «до» (S0).

## Спринт 4 — Таблицы отчётов (УТП!) — ТОЛЬКО «переодеть», не заменять на B24Table

> ⚠️ **КРИТИЧНО (риск УТП):** НЕ заменять рекурсивные таблицы на `B24Table`. `B24Table` поддерживает дерево только через `:get-sub-rows="row => row.children"` (ОДНОРОДНЫЕ children), а у нас **гибридная неоднородная иерархия** (узел → `children` ИЛИ `employees` → `items`, разные колонки/метки на уровнях). Замена = риск сломать УТП. Делаем **ре-скин существующих рекурсивных Vue-компонентов**: меняем только классы `ms-table*` → нативные токены/классы, логику и разметку строк НЕ трогаем.

## Порядок и распределение моделей (резюме)

| Спринт | Содержание | Риск | Обратимость | Модель |
|---|---|---|---|---|
| S0 | Пин версии + защитная сетка/скриншоты | нет | тривиально | Sonnet/ручное |
| S1 | Токены → нативный вид (1–2 файла) | низкий | revert 1–2 файлов | Sonnet |
| S2 | Каркас страниц/карточки (по странице) | низкий | по странице | Sonnet (эталон) + Haiku |
| S3 | Модалки/тосты/empty/бейджи/табы/формы | низкий–средний | по компоненту | Sonnet (overlay/toast) + Haiku |
| S4 | **Таблицы отчётов — ре-скин (УТП)** | **высокий** | revert спринта | **только Sonnet** |
| S5 | `embedded.vue` + чистка + (опц.) dark | высокий | revert изолированно | Sonnet + Haiku |

Каждый спринт реализуется через `subagent-driven-development` (свежий субагент на задачу + spec-ревью + code-ревью), затем гейт смоук-чек-листа, затем merge+push или откат.

# Спринт 3 — ИНН-UX: незаполненные проекты, окно заполнения/замены, прогресс с питомцем

## Контекст
После выхода Спринта 2 на прод и реального использования дозаполнения ИНН появились запросы:
видеть проекты без данных для ИНН; заполнять/менять ИНН на проект целиком (а не выбирать карточки);
заменять уже проставленный ИНН при смене юр.лица; единый прогресс-индикатор; убрать дублирующие кнопки.

## Принятые решения
| Развилка | Решение |
|---|---|
| Что такое «незаполненный проект» | **Любое** из: нет компании-клиента (`company_id`), нет нашего юр.лица (`our_legal_entity_id`), ИНН не резолвится из реквизитов (`RQ_INN`). |
| Замена ИНН (смена юр.лица) | **Только через «окно заполнения ИНН»** (модалка проекта) с явным выбором «Перезаписать всё». Глобального тумблера нет. |
| Прогресс-бар | **Везде** (ИНН-простановка, синхронизация, экспорты), переиспользуемый `ProgressOverlay` с маскотом **🦫 Бобёр-Учётчик**. |

Мокап: [docs/internal/mockups/inn/02-sprint3-enhancements.html](docs/internal/mockups/inn/02-sprint3-enhancements.html).

## Фичи и архитектура

### Ф1. Настройки → «Незаполненные проекты»
- **Бэк:** `GET /api/projects/health` → `inn_backfill_service` (или новый `project_health_service`): по `get_project_card_queryset(account)` + картам ИНН (`ProjectCardService.get_companies()/get_legal_entities()`) формирует список проектов с флагами `has_company`, `has_legal_entity`, `client_inn`, `our_inn`. Возвращает только «незаполненные» (есть хотя бы один пробел).
- **Фронт:** страница/секция в настройках (`pages/settings/projects-health.client.vue` + пункт в `settings/index`). Таблица: Проект · Клиент · Наше юр.лицо · ИНН клиента · Наш ИНН · «Открыть проект» (переход к доске/карточке). Подсветка: красное — отсутствует, жёлтое — нет ИНН в реквизитах, зелёное — ок.
- `stores/api.ts`: метод `getProjectsHealth()`.

### Ф2. ИНН-панель: сворачивание + окно заполнения/замены
- **Сворачивание групп (аккордеон):** локальное состояние раскрытия на группу в `InnBackfillPanel.vue`. По умолчанию — раскрыто (как сейчас), клик по шапке группы сворачивает; в шапке всегда видна сводка (кол-во, готов/внимание).
- **«Окно заполнения ИНН» (модалка)** — новый `components/reports/InnAssignModal.vue`. Открывается кнопкой группы «Заполнить / Изменить ИНН →». Поля: наш ИНН и ИНН клиента (предзаполнены резолвом, **редактируемые**); выбор области: «Только пустые поля» / «Перезаписать всё (смена юр.лица)». Кнопка «Применить к проекту».
- **Бэк (проектная простановка/замена):** `POST /api/inn-backfill/apply-project` → `InnBackfillService.apply_project(project_id, date_from, date_to, our_inn, client_inn, overwrite)`:
  - читает карточки СП за период с фильтром по проекту (включая уже заполненные);
  - `overwrite=False` → пишет только в пустые; `overwrite=True` → перезаписывает непустые переданными значениями;
  - запись `crm.item.update` чанками с throttle (как в `apply`), лимит/чанк сохраняется.
  - `stores/api.ts`: метод `applyInnProject(...)`.
- **«Заполнить всё возможное»** — без изменений (массово в пустые по всем проектам).

### Ф3. Прогресс-оверлей с питомцем (переиспользуемый)
- **`components/common/ProgressOverlay.vue`** — пропсы: `visible`, `title`, `done`, `total`, `label?`. Рендерит затемнение + карточку с прогресс-баром, процентом и анимированным **🦫 Бобром-Учётчиком**, который «тащит» карточку 🗂 по бару; при 100% — штамп ✅. Чистый CSS-анимация, без сторонних зависимостей.
- **Подключение:** ИНН-простановка (`InnBackfillPanel` apply + `InnAssignModal`), синхронизация (`raw-data` handleSync), экспорты (raw-data/отчёты). Прогресс там, где есть чанки/этапы; где операция атомарная — индикатор «идёт…» с неопределённым баром (бобёр бежит на месте).

### Ф4. Убрать дублирующие кнопки
- В `pages/reports/raw-data.client.vue` кнопки шапки `B24Card` «Синхронизировать с Б24» / «Обновить» показывать только на вкладке «Выгрузка» (`v-if="activeTab === 'export'"`), либо перенести в контент вкладки. На вкладке «Дозаполнение ИНН» действия — только в самой панели.

## Затрагиваемые файлы
- **Бэк:** `inn_backfill_service.py` (+`apply_project`, +health-логика или новый `project_health_service.py`), `views.py` (+`projects_health`, +`inn_backfill_apply_project`), `urls.py`, тесты `tests_inn_backfill.py`.
- **Фронт:** новый `components/common/ProgressOverlay.vue`, новый `components/reports/InnAssignModal.vue`, новый `pages/settings/projects-health.client.vue`, изменения `components/reports/InnBackfillPanel.vue`, `pages/reports/raw-data.client.vue`, `pages/settings/index.client.vue`, `stores/api.ts`, `types/inn.ts`.

## Риски
- **Замена (overwrite)** меняет прод-данные в Bitrix → обязательное подтверждение в модалке + чёткое предупреждение; лог результата.
- Проектная простановка читает все карточки проекта за период (включая заполненные) → объёмы; чанкинг + лимит как в `apply`.
- Резолв «health» по всем проектам + реквизитам → кэш `get_companies/get_legal_entities` уже есть; не делать N запросов.

## Верификация (e2e)
1. Настройки → «Незаполненные проекты»: список корректен, подсветка верна, «Открыть проект» ведёт к карточке.
2. ИНН-панель: группы сворачиваются; «Заполнить/Изменить ИНН» открывает модалку; «Только пустые» и «Перезаписать всё» работают (проверить в Bitrix, что значения изменились).
3. Прогресс-оверлей с бобром виден при простановке/синке/экспорте; по завершении закрывается.
4. На вкладке ИНН нет кнопок «Синхронизировать/Обновить».
5. Юнит-тесты на `apply_project` (overwrite vs только пустые) и health-логику.

# Презентация модуля «Учёт трудозатрат» — дизайн

Дата: 2026-07-29
Статус: утверждён заказчиком, в реализации

## Задача

Три версии презентации продукта под три аудитории: холодные клиенты, тёплые клиенты, агентства.
Каждая версия содержит: боли, роадмап, сценарий работы, требования и ограничения, мокапы интерфейса.

## Решения

| Вопрос | Решение |
|---|---|
| Кто такие «агенты» | Агентства как **клиентский сегмент** (биллинг клиентов по часам), не канал продаж |
| Формат | HTML-слайды 16:9, навигация с клавиатуры, печать в PDF через браузер |
| Сборка | **Три отдельных self-contained файла** — `cold.html`, `warm.html`, `agency.html` |
| Цены | Слайд тарифов есть, **цифры — плейсхолдеры** («уточняется»), цены не публикуем |
| Демоданные | **Одна сквозная компания** на все три версии, цифры сходятся между экранами |
| Мокапы | Вёрстка в стиле Bitrix24 UI Kit (светлая тема, синий), не скриншоты |

### Как снимается минус трёх файлов

Заказчик выбрал три независимых файла ради стерильности каждой версии. Чтобы правка мокапа не
означала три ручные правки, исходники лежат в `_src/`, а три файла **генерируются**:

```
marketing/presentation/
├── _src/
│   ├── deck.css        # стили слайдов и мокапов — один экземпляр
│   ├── deck.js         # навигация — один экземпляр
│   ├── mockups.html    # библиотека мокапов — один экземпляр
│   ├── cold.html       # только контент холодного трека
│   ├── warm.html       # только контент тёплого трека
│   └── agency.html     # только контент агентского трека
├── build.py            # инлайнит css/js/мокапы → три self-contained файла
├── cold.html           # ← результат, отправляется клиенту как одно вложение
├── warm.html
└── agency.html
```

Мокап вставляется в трек маркером `<!--mockup:project-task-->`. `build.py` — чистый Python без
зависимостей, запускается `python3 marketing/presentation/build.py`.

Результат для получателя — ровно то, что выбрано: три независимых файла без внешних запросов.

## Контент

### Боли (холодный трек)

- Месяц закрыт, а куда ушли часы — неизвестно: время оседает в комментариях, чатах и головах.
- Проект выглядит прибыльным, но денег нет: себестоимость по факту никто не считает.
- Клиент спорит по счёту, а подтвердить объём работ нечем.
- Сводка по часам — это два дня ручной сборки в Excel.

### Боли (агентства)

- Часы, которые не выставили: правки «по-быстрому» и скоуп-крип уходят в подарок клиенту.
- Овертайм за свой счёт: команда перерабатывает, в счёт это не попадает.
- Спор об объёме работ без детализации по задачам.
- Непонятно, какой клиент реально прибыльный, а какой съедает маржу.

### Почему не альтернативы (тёплый трек)

- **Встроенный учёт Битрикс24** — есть часы по задаче, но нет проектного разреза, денег,
  разделения оплачиваемых и внутренних часов, управленческих отчётов и выгрузки в 1С.
- **Excel** — ручная сборка, рассыпается при росте, не связан с задачами.
- **Внешний тайм-трекер** — отдельное окно и двойной ввод, данные уезжают за контур компании.

### Требования

- Битрикс24 (облако или коробка) с доступными смарт-процессами.
- Права администратора для установки и первичной настройки.
- Разрешения приложения на CRM, задачи, пользователей и встройки.
- ~15 минут на мастер настройки: смарт-процесс и поля создаются в один клик.
- Для выгрузки в 1С — заполненные реквизиты (ИНН) компаний и юрлиц.

### Ограничения (даём честно, отдельным слайдом)

- Отчёты строятся по локальной копии данных: показывают состояние на момент синхронизации,
  а не «прямо сейчас».
- Финансовый контур — бюджет проекта, план-факт, доходы и расходы — в разработке,
  в текущей версии его нет.
- Ставка задаётся глобально и на карточке проекта, ставки по конкретному сотруднику нет.
  На каждой записи сохраняется снимок ставки (`hourly_rate_snapshot`), поэтому смена ставки
  не переписывает историю.
- Тёмной темы пока нет.
- У разовой выгрузки есть практический потолок по объёму периода.

> Расхождение для отдельной задачи: в тексте на Маркетплейсе написано «ставка сотрудников»,
> в коде ставка проектная (`ProjectCard.hourly_rate`). Текст на Маркетплейсе стоит поправить.

### Где живёт приложение

Вкладки биндятся в трёх местах: карточка задачи (`TASK_VIEW_TAB`), группа/проект
(`SONET_GROUP_DETAIL_TAB`), сделка (`CRM_DEAL_DETAIL_TAB`).

### Роадмап — каркас (черновик, заказчик заменит своим текстом)

- **Сейчас в проде:** учёт в задаче, дерево проект → задача → подзадача, Split, семь отчётов,
  доска проектов, выгрузка в Excel, ИНН → 1С.
- **Ближайшее:** финансовый контур — бюджет проекта, план-факт по часам и деньгам,
  доходы и расходы, связь со сделками.
- **Дальше:** напоминания о незаполненных часах, ставки по ролям и сотрудникам,
  тёмная тема, мобильный сценарий.

Слайд помечен как черновик, текст блоков заменяется без правки вёрстки.

Free: учёт времени, базовые отчёты, доска проектов. Paid: финансовый контур (в разработке).

## Технические требования к вёрстке

- Слайды 16:9, вписываются по высоте окна; контент не обрезается на 1280×720 и выше.
- Навигация: `→`/`↓`/`Space`/`PageDown` вперёд, `←`/`↑`/`PageUp` назад, `Home`/`End`,
  клик по краям экрана, обычный скролл. Счётчик слайдов в углу.
- Печать: `Ctrl+P` даёт по одной странице на слайд, ландшафтная ориентация.
- Ноль внешних запросов: стили инлайн, иконки — инлайновые SVG, шрифты системные.
- Светлая тема, палитра Bitrix24 (синий акцент), нейтральный фон слайдов.
- Файл открывается по `file://` без веб-сервера.

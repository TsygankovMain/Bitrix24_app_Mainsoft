# Выкатка dev_ver2.0 в прод

Документ готовит слияние `dev_ver2.0` → `prod_2026`. Пуш в `prod_2026` сразу выкатывает приложение на Timeweb App Platform, поэтому делается только по отдельной команде.

Состояние на 13.09.2026: ветка плюс волна исправлений багов уровня «высоко» и «средне» из аудита.

## Что едет

**Для всех порталов, бесплатно:**

- Новый дизайн в стиле портала Битрикс24: главная, навигация по разделам, доска проектов с боковой панелью вместо раскрытия внизу, пересобранный канбан, вкладка в карточке задачи.
- Пересобранный экран «Настройки → Сопоставление полей»: шесть шагов вместо одной формы, баннер состояния настройки на всех экранах.
- Страница «Pro» с описанием тарифа и формой запроса счёта.

**Тариф Pro — 3000 ₽ в месяц за портал:**

- Счёт и акт за период, по проекту или по выбранным задачам. Счёт создаётся штатным смарт-счётом CRM, акт печатается генератором документов портала. Выгрузка детализации в Excel: задача → сотрудник → списание.
- БДДС по проектам и раздел «Начисления и списания» (операции смарт-процесса «Доходы-расходы»).
- Ролевая модель: администратор, бухгалтерия, руководитель проекта, сотрудник; права редактируются матрицей.

## Что увидят пользователи в первый день

1. **Pro не включён ни у кого.** Разделы счетов, БДДС и ролей видны с замком и ссылкой на страницу «Pro». Учёт часов, отчёты и выгрузки работают как раньше: ни одна прежняя функция за тариф не закрыта.
2. **Права не меняются.** Без тарифа ролевая модель не действует, у всех прежние права.
3. **Жёлтый баннер «Часть полей не сопоставлена» или «Проекты не подключены».** Он появится у портала, где:
   - не выбран смарт-процесс проектов;
   - или не сопоставлено хотя бы одно поле для отчётов.

   Баннер сворачивается, работу не блокирует. Заранее посчитать такие порталы нельзя: конфигурация лежит в `app.option` клиентских порталов, а не в нашей базе. Это главный источник вопросов в поддержку в первую неделю.
4. **Новый интерфейс.** Кнопки и разделы переехали, стоит предупредить клиентов коротким сообщением.

## Миграции

В проде применены миграции по `0021_closedperiod`. Поедут 0022–0029:

| Миграция | Что делает | Риск |
|---|---|---|
| 0022_billing | новые таблицы документов, строк и записей счёта + `PortalFeature`, частичный уникальный индекс | нет: таблицы пустые |
| 0023_billing_invoice_print | 6 полей в новой таблице документов | нет |
| 0024_portal_subscription | таблицы тарифа и журнала; перенос строк `PortalFeature` в тариф | нет: `PortalFeature` в проде пуст, перенос ничего не сделает |
| 0025_delete_portalfeature | удаляет `PortalFeature` | нет |
| 0026_portal_roles | роли и состояние ролей портала | нет |
| 0027_pro_purchase | заявки на Pro, код портала, нумератор счетов | нет |
| 0028_portal_permission_matrix | матрица прав и журнал её изменений | нет |
| 0029_billing_entry_portal_unique | частичный уникальный индекс «одно активное выставление часов на портал» (действует только при заполненном `portal`) | нет: таблица пустая |
| 0030_pro_request_crm_task_id | поле `crm_task_id` в заявке на Pro — id задачи tasks.task.add на контроль оплаты | нет: только новое поле, значение по умолчанию `''` |

Ни одна миграция не меняет существующие таблицы. Объёмы в проде на 13.09.2026: `timesheet_item` 26,5 тыс. строк, `portal_user` 4,6 тыс., `portal_task` 3,3 тыс., `project_card` 469, `bitrix24account` 182, `portal` 6 — в миграциях не участвуют, блокировок на них нет.

## Переменные окружения на Timeweb

| Переменная | Что сделать |
|---|---|
| `APP_ENV_LABEL` | **не задавать.** Иначе на каждом экране будет метка стенда |
| `BUILD_TARGET` | оставить `production`. Команда `billing_demo_data` в проде отказывается запускаться |
| `MAINSOFT_BILLING_WEBHOOK` и прочие `MAINSOFT_BILLING_*` | **пока не задавать.** Без вебхука заявка на Pro сохраняется в нашей базе со статусом «ожидает отправки», в CRM Mainsoft ничего не уходит, форма честно пишет, что счёт подготовят вручную. Заявки видны командой `pro_requests list` |

Новый фоновый цикл в `start.sh`: раз в 15 минут `pro_requests sync --quiet`. Без вебхука ничего не отправляет.

Когда решат включать автоотправку — минимальный набор переменных:
`MAINSOFT_BILLING_WEBHOOK` (права `crm`, `task`, `im`, `documentgenerator`),
`MAINSOFT_BILLING_MY_COMPANY_ID` (обязательно — без юрлица продавца смарт-счёт
не выставить), `MAINSOFT_BILLING_NOTIFY_USER_ID`. Сделка необязательна:
`MAINSOFT_BILLING_DEAL_CATEGORY_ID` пуст — счёт выставляется напрямую на
компанию клиента, без сделки; задан — сделка создаётся, как раньше, и счёт
привязывается к ней. В обоих случаях по счёту создаётся задача
tasks.task.add «проконтролировать оплату» (ответственный —
`MAINSOFT_BILLING_TASK_RESPONSIBLE_ID`, иначе `MAINSOFT_BILLING_RESPONSIBLE_ID`,
иначе `MAINSOFT_BILLING_NOTIFY_USER_ID`). Полный список — в
`.env.example` и докстринге `main/pro_purchase_crm.py`.

## Порядок выкатки

1. Бэкап базы `default_db` в панели Timeweb, записать время.
2. Слить `dev_ver2.0` в `prod_2026` через PR — по команде.
3. Дождаться сборки на Timeweb. Миграции применяются при старте контейнера.
4. Пройти чек-лист ниже.

## Откат

- Код: откатить PR в `prod_2026` (revert merge-коммита) и дождаться сборки.
- База: **до** отката кода выполнить в контейнере `python manage.py migrate main 0021`. Миграции обратимы и удаляют только новые таблицы. Всё, что успели создать в новых разделах — счета, роли, заявки на Pro, — пропадёт, но счета останутся в CRM порталов.
- Если миграции откатить не удалось — восстановить бэкап из шага 1.

## Чек-лист после выкатки

- [ ] Контейнер поднят, в логах нет ошибок миграций; `python manage.py showmigrations main` показывает 0030.
- [ ] Вкладка в карточке задачи открывается, часы записываются и видны в отчёте.
- [ ] Главная, доска проектов и отчёты открываются у обычного сотрудника и у администратора.
- [ ] Выгрузка отчёта в Excel скачивается.
- [ ] Метки `DEV_ver2` нет ни на одном экране.
- [ ] Разделы «Счета», «БДДС», «Роли» показывают замок, а не ошибку.
- [ ] Страница «Pro» открывается; тестовая заявка сохраняется (`pro_requests list`), затем отменить её: `pro_requests cancel`.
- [ ] `python manage.py pro_plan list` — все порталы без тарифа.
- [ ] Через час: фоновые синхронизации идут (`SyncRun` / логи), нет всплеска 500 в `request_log`.

## Открытые решения до включения Pro клиентам

- НДС в счёте на Pro: решено — Mainsoft работает без НДС, `PRO_VAT_MODE` по умолчанию `none`.
- Закрепить ли «видеть суммы» за ролью «Администратор».
- Вебхук `MAINSOFT_BILLING_WEBHOOK` для автоматической отправки заявок в CRM Mainsoft (плюс `MAINSOFT_BILLING_MY_COMPANY_ID` и `MAINSOFT_BILLING_NOTIFY_USER_ID` — минимальный набор, см. таблицу переменных выше).
- Баги уровня «высоко» и «средне» из аудита закрыты волной исправлений; низкие и план оптимизации — в отчётах аудита на claude.mainsoft.su.

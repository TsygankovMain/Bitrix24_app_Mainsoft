# Редизайн «Учёта трудозатрат»: четыре варианта

11.09.2026. Макеты всех вариантов — в [2026-09-11-redesign-options.html](./2026-09-11-redesign-options.html). У каждого варианта три экрана: главная полной версии, один ключевой экран и вкладка задачи со списанием часов (в узкой рамке 660 / 480 / 400 px). Данные в макетах вымышленные.

Код приложения не менялся. Макеты — основа для обсуждения, а не ТЗ.

## Как подбирали

Работали по методике скила UI UX Pro Max, по его локальной базе.

- **Дизайн-система** (запрос «B2B SaaS time tracking timesheet enterprise dashboard», плотность 8, вариативность 3). Взят стиль Minimalism & Swiss («enterprise apps, dashboards, SaaS»). Паттерн «Hero + Features + CTA» из того же ответа отброшен: он для лендингов, а у нас рабочий инструмент.
- **Стили:** Data-Dense Dashboard (вариант B), Bento Box Grid (вариант C). Для командной палитры в базе стилей совпадений нет (два запроса). Решение для варианта D опирается на общие принципы и документацию UI Kit: там есть `B24CommandPalette` с `defineShortcuts`.
- **Палитры:** Productivity Tool (бирюзовый фокус + оранжевое действие) взята для варианта D. Financial Dashboard отброшена: тёмный фон по умолчанию, а скил сам советует его избегать. В вариантах A–C палитра строится от синего Битрикс24.
- **Шрифты.** Plus Jakarta Sans из дизайн-системы отброшен: в базе у него только `cyrillic-ext`, а базовой кириллицы нет. Взяты шрифты с подтверждённой кириллицей: Onest (B), Manrope (C), Fira Sans + Fira Code (пара «Dashboard Data», D). В варианте A — системный шрифт, как у портала.
- **UX-правила из базы:**
  - широкие таблицы — горизонтальный скролл или карточки на узкой ширине;
  - массовые действия — через выбор строк;
  - недоступное — приглушённым, с курсором «нельзя»;
  - пустое состояние — с подсказкой и действием;
  - полная работа с клавиатуры и видимый фокус;
  - обратная связь после отправки формы;
  - подписи у полей, а не только плейсхолдеры.
- **Контраст.** Для ключевых пар посчитан по формуле WCAG. Белый и тёмный текст на `#0075ff` дают ≈4,2:1 — это ниже AA для обычного текста. Поэтому в B–D кнопки темнее (`#0062d6`, ≈5,6:1). В A оставлен нативный синий, чтобы совпадать с порталом.

## Что сейчас мешает

По коду ветки `dev_ver2.0`:

1. **Нет постоянной навигации.** Каждый раздел — отдельная страница с «Назад». Семь отчётов — плитки внизу главной. «Закрытие месяца» и «Проверка данных (ИНН)» спрятаны в «Настройках» рядом с диагностикой.
2. **Три разных каркаса страниц:** `B24PageHeader`, `ms-page-shell` + `ProseH2` и самописная вёрстка вкладки задачи.
3. **Вкладка задачи не рассчитана на узкий фрейм.** В `embedded.vue` сетка `1fr 380px` без брейкпоинта. При фрейме 640 px дереву задач остаётся около 230 px, на 400 px вёрстка ломается.
4. **Остатки лаймового бренда во вкладке задачи:** иконка `#d9f99d`, ховер кнопки `#c7f04f`, лаймовая тень.
   - Тёмный текст на синей кнопке — контраст ≈4,2:1.
   - «Изменить» и «Удалить» видны только при наведении, на тачскрине их нет.
5. **Лишнее на экране сотрудника.** Редактируемое поле «Стоимость часа» и «Сумма для клиента» доступны каждому, кто открыл задачу.
6. **Два экрана списания:** `task.vue` (модалка) и `embedded.vue` (две колонки). Прод смотрит на `/embedded`.

## Общее для всех вариантов

Эти решения не зависят от выбора концепции. Их стоит делать в любом случае.

- **Один экран списания.** Остаётся `embedded.vue`, `task.vue` уходит.
- **Вкладка задачи — одна колонка.** Раскладка перестраивается по ширине: 660 → 480 → 400 px.
- **Действия у записи видны всегда** (меню «⋯»), а не только при наведении.
- **Форма списания — не модалка внутри фрейма.** Фрейм растёт по высоте контента (`requestIframeAutoHeight`), и центрированная модалка может оказаться за краем видимой области. Варианты:
  - слайдер портала (в проекте уже есть лейаут `slider`);
  - раскрытие прямо в списке;
  - строка быстрого ввода.
- **«Стоимость часа» уходит из вкладки задачи.** Сумму видят только руководители.
- **Места под две платные функции** — «БДДС по проектам» и «Счёт и акт по фильтру». Состояния:
  - **не подключено:** замок, бейдж «по подписке», короткое описание пользы. Кнопка «Подключить» — только администратору, остальным — «Попросить администратора»;
  - **пробный период:** бейдж «пробный, осталось N дней»;
  - **подключено:** обычный пункт меню без бейджа.

  Состояние отдаёт бэкенд: нужен эндпоинт статуса подписки. Как именно проверять лицензию в Маркетплейсе, ещё не прорабатывали.

## Вариант A. Родной портал

Смелость 1/4, эволюция текущего UI Kit.

**Идея.** Приложение выглядит как штатный раздел Битрикс24: горизонтальное меню раздела, фильтр в строку как в CRM, форма списания в слайдере портала.

**Для кого.** Все роли. Особенно сотрудники, которые открывают приложение редко и должны узнавать интерфейс портала без обучения.

**Что меняется.**
- **Меню раздела:** Главная, Проекты, Отчёты (7 отчётов в двух группах), Контроль (закрытие месяца, проверка данных, со счётчиком проблем), Финансы (две платные функции), шестерёнка настроек.
- **Главная:** четыре KPI за выбранный месяц, включая статус закрытия месяца. Проекты — таблица с быстрыми фильтрами вместо карточек-кнопок. Справа — панель проекта.
- **Отчёты:** единая шапка, фильтр в одну строку с сохранёнными пресетами, свежесть данных и итоги в одном месте. Рекурсивная таблица не трогается.
- **Вкладка задачи:** одна колонка, итоги задачи в одной строке, «+» у каждой задачи и подзадачи. Внизу закреплены «В отчёт Битрикс24» и «Excel». Форма — в слайдере, с быстрыми кнопками даты и часов.

**Плюсы.**
- Минимальный риск и самый короткий путь.
- Нулевая стоимость обучения.
- Всё собирается из готовых компонентов UI Kit: `B24NavigationMenu` (горизонтальный, с бейджами и выпадающими пунктами), `B24Badge`, `B24Slideover`, `B24Table`.

**Минусы.**
- Не добавляет новых сценариев: сотрудник так же сам ищет задачу, руководитель — отчёт.
- Выглядит «как всё в портале», продуктового отличия мало.

**Риски совместимости.** Низкие.
- Горизонтальное меню на 1000 px вмещает 5 пунктов и шестерёнку. Шестой пункт уже потребует «Ещё».
- Слайдер для формы — это переход на отдельный маршрут приложения в слайдере. Нужно проверить, что после сохранения вкладка задачи обновляется: слайдер закрывается, событие приходит во фрейм.
- Закреплённый футер во фрейме с автовысотой прилипает к низу контента, а не к низу экрана. На длинном дереве его придётся сделать обычным блоком.

**Оценка.**
- Машинная часть: **18–26 ч**:
  - каркас навигации в `default.vue` и маршруты — 4–6 ч;
  - главная — 3–4 ч;
  - единая обвязка 7 отчётов и строка фильтра — 5–7 ч;
  - вкладка задачи со слайдером — 5–7 ч;
  - места под «Финансы» — 1–2 ч.
- Ручная часть: **10–14 ч**:
  - проверка на портале на трёх ширинах, в карточке задачи и в слайдере — 4–6 ч;
  - сверка цифр 7 отчётов с текущими — 3–4 ч;
  - приёмка с пользователями — 3–4 ч.

## Вариант B. Рабочее место по ролям

Смелость 2/4, дашборд.

**Идея.** Главная сама показывает, что делать сегодня: сотруднику — его неделю и задачи без списаний, руководителю — проекты под риском, бухгалтеру — готовность месяца к закрытию.

**Для кого.** Руководители проектов и бухгалтер в первую очередь. Сотрудники — через «Моя неделя» и быструю строку во вкладке задачи.

**Что меняется.**
- **Навигация:** вертикальный сайдбар внутри приложения (`B24SidebarLayout` уже стоит в `default.vue`), сворачивается до иконок. Группы: «Работа», «Контроль» (со счётчиками), «Финансы» (с замками), «Настройки».
- **Главная — виджеты по роли** (переключатель «Сотрудник / Руководитель / Бухгалтер»):
  - моя неделя против нормы;
  - задачи без списаний;
  - проекты под риском;
  - закрытие месяца;
  - проверка данных;
  - закрытые виджеты БДДС и «Счёт и акт» с размытым превью.
- **Доска проектов:** плотные карточки (название, компания, освоение, факт/план, куратор-аватар) и переключатель «Канбан / Таблица / Хронология / Архив».
- **Вкладка задачи:** строка быстрого ввода сверху — задача, дата, часы (кнопки 0,5 / 1 / 2 / 4), «учитывать», описание, «Отразить». Правка записи раскрывается прямо в списке. «Разделить» и «Удалить» — в меню «⋯». Над списком — освоение оценки задачи.

**Плюсы.**
- Меньше кликов на частые действия: списание в одну строку без открытия формы.
- Проблемы (перерасход, пустые ИНН, опоздавшие записи) видны сразу.
- Естественное место для платных функций.
- Виджеты — те же `B24Card`.

**Минусы.**
- Главная требует новых данных: 3–4 эндпоинта для «моей недели», «задач без списаний» и счётчиков контроля.
- Нужна модель ролей. Сейчас её нет, роль придётся определять по правам портала или задавать в настройках.
- Сайдбар забирает 200–240 px из фрейма 1000 px.

**Риски совместимости.** Средние.
- В UI Kit нет графиков. Столбики недели и полосы освоения — на своём SVG/CSS или отдельной библиотеке.
- Вертикальный `B24NavigationMenu` есть в документации, но версия в проекте (2.5.3) не сверена.
- Виджеты с тяжёлыми запросами замедлят открытие главной. Их нужно грузить независимо, со скелетонами.

**Оценка.**
- Машинная часть: **45–65 ч**:
  - сайдбар и маршруты — 6–8 ч;
  - главная с виджетами и 3–4 эндпоинтами — 18–26 ч;
  - доска — 6–8 ч;
  - вкладка задачи с быстрой строкой и правкой в списке — 10–14 ч;
  - «Финансы» — 2–3 ч.
- Ручная часть: **22–30 ч**:
  - права и роли на реальном портале;
  - корректность цифр в виджетах на живых данных;
  - нагрузка новых эндпоинтов;
  - приёмка с тремя ролями.

## Вариант C. Проект в центре

Смелость 3/4, бенто-карточки.

**Идея.** Всё строится вокруг проекта: у каждого проекта есть «карточка 360» с часами, командой, задачами, бюджетом, а дальше — с финансами и документами.

**Для кого.** Руководители проектов и директор, которым важен разрез «проект целиком». На платных функциях это даёт максимальную выгоду: и БДДС, и акты привязаны к проекту.

**Что меняется.**
- **Навигация:** верхние вкладки-разделы с иконками («Обзор, Проекты, Отчёты, Контроль, Финансы»).
- **Главная — бенто-сетка:** мои проекты с кольцами освоения, списано сегодня, закрытие месяца, «потери выручки» деньгами, компактный список отчётов, закрытые плитки БДДС и «Счёт и акт».
- **Новый экран «Карточка проекта»:**
  - освоение бюджета;
  - часы по неделям;
  - команда;
  - топ задач по часам;
  - финансовый итог;
  - вкладки «Финансы» и «Документы» с замками.

  Этот экран может стать содержимым вкладки группы проекта (`SONET_GROUP_DETAIL_TAB` сейчас ведёт на отчёт по проекту).
- **Вкладка задачи:** карточки задачи и подзадач, в каждой — полоса «учтено / не учтено», быстрые кнопки «+0,5 / +1 / +2» и две последние записи.

**Плюсы.**
- Сильная продуктовая история для продаж: «проект как на ладони».
- Естественная витрина для БДДС и актов.
- Карточка проекта заменяет несколько переходов между доской, отчётом и группой.

**Минусы.**
- Самый большой объём новой агрегации данных: карточка проекта собирает доску, отчёты и финансы.
- Бенто-сетка хуже масштабируется на 30+ проектов, чем таблица.
- Быстрые «+1 ч» без описания рискуют дать записи без комментария. Нужно обязательное описание или короткий шаг подтверждения.

**Риски совместимости.** Средние.
- Сетка своя (CSS grid поверх `B24Card`).
- Веб-шрифт Manrope отличается от шрифта портала, приложение будет выглядеть «чужим». Шрифт лучше разместить у себя: Google Fonts из РФ бывает медленным.
- Кольца и мини-графики — свой SVG.

**Оценка.**
- Машинная часть: **55–75 ч**:
  - навигация и главная — 12–16 ч;
  - карточка проекта с эндпоинтом агрегации — 22–30 ч;
  - вкладка задачи — 10–14 ч;
  - закрытые плитки и «Финансы» — 3–4 ч;
  - адаптив бенто — 4–6 ч.
- Ручная часть: **24–32 ч**:
  - сверка агрегатов карточки с отчётами;
  - проверка во вкладке группы;
  - приёмка у руководителей проектов.

## Вариант D. Лента времени и палитра команд

Смелость 4/4, радикальный.

**Идея.** Приложение переходит от «отчётов про часы» к «неделе, которую я заполняю»:
- главная — таймшит недели;
- любое действие — через палитру команд (Ctrl/⌘+K);
- во вкладке задачи — лента по дням и ввод одной фразой.

**Для кого.** Сотрудники, которые списывают часы каждый день. Опытные пользователи, которым важна скорость и клавиатура.

**Что меняется.**
- **Навигация:** почти нет меню. Верхняя строка поиска открывает палитру с группами «Быстрые действия» (отразить часы, закрыть месяц), «Недавние», «Отчёты», «Проекты», «Финансы · по подписке».
- **Главная:** таймшит «проект/задача × дни недели» с итогами и нормой, переключатель «Я / Команда», статус месяца внизу.
- **Отчёт «Ежедневная нагрузка»:** тепловая карта «сотрудники × дни» с подсказкой по ячейке.
- **Вкладка задачи:**
  - строка «2ч вчера обработка ошибок обмена»;
  - под ней — разобранные поля: часы, дата, «учтено», задача — видно, что поймёт система;
  - лента записей по дням, фильтр подзадач чипами.

**Плюсы.**
- Самый быстрый ежедневный ввод.
- Сильный вау-эффект на демо.
- Палитра даёт одно место для всех действий, включая платные.
- Тепловая карта нагрузки нагляднее текущей матрицы.

**Минусы.**
- **Сменяется модель работы.** Сотрудники привыкли списывать из задачи, а таймшит «проект × день» не знает конкретную задачу: при вводе в ячейку нужен выбор задачи.
- **Ввод фразой нужно разбирать.** Русские даты («позавчера», «в пн») и часы («1,5ч», «полтора часа»). Встроенные `\w` и `\b` не видят кириллицу, это известная ловушка.
- Палитра не помогает тем, кто не знает о Ctrl+K. Кнопка поиска обязательна.

**Риски совместимости.** Высокие.
- **Ctrl/⌘+K срабатывает, только когда фокус внутри фрейма.** У портала свой поиск. В Firefox Ctrl+K при фокусе вне страницы уходит в поиск браузера.
- **Редактируемый таймшит пишет в смарт-процесс через бэкенд.** Нужно соблюдать закрытый месяц и иерархию задач, ячейка без задачи недопустима.
- **Шрифты.** Fira Sans и Fira Code отличаются от портала.
- **Цвета.** Бирюзовый акцент вместо синего Битрикс24 — визуальный разрыв с порталом.
- `B24CommandPalette` есть в документации UI Kit, но в версии 2.5.3 не сверен.

**Оценка.**
- Машинная часть: **75–110 ч**:
  - палитра с индексом проектов, задач, отчётов и действий — 14–20 ч;
  - таймшит с записью — 22–32 ч;
  - разбор фразы с тестами — 10–16 ч;
  - тепловая карта — 8–12 ч;
  - лента во вкладке задачи — 12–18 ч;
  - «Финансы» — 3–4 ч;
  - адаптив — 6–8 ч.
- Ручная часть: **32–45 ч**:
  - сценарии ввода на реальных фразах;
  - конфликты клавиш в портале и браузерах;
  - закрытый месяц;
  - обучение и приёмка.

## Рекомендация

**Каркас взять из A, из B взять две вещи, остальное — позже, по мере платных функций.**

Первая итерация:

1. **Каркас A:**
   - горизонтальное меню раздела с пунктами «Контроль» и «Финансы» и состояниями «не подключено / пробный / подключено»;
   - единая обвязка отчётов;
   - таблица проектов на главной.
2. **Вкладка задачи.** Одна колонка из A плюс строка быстрого ввода из B: задача, дата, часы кнопками, «учитывать», описание. Правка — в слайдере или раскрытием в списке. Заодно убрать `task.vue`, лайм, поле ставки, кнопки только-при-наведении.
3. **Счётчики «Контроля»** (незакрытый месяц, пустые ИНН, опоздавшие записи) — из B. Данные для них уже есть в `settings/periods` и проверке ИНН.

Оценка первой итерации:
- машинная часть — **24–32 ч**;
- ручная — **12–16 ч**: проверка на портале на трёх ширинах, сверка отчётов, приёмка вкладки задачи сотрудниками.

Дальше:
- **Когда запускается БДДС** — делать карточку проекта из C: БДДС естественно живёт внутри проекта.
- **Палитру команд из D** добавлять поверх готового каркаса, как ускоритель для опытных пользователей, а не как замену меню.
- **Таймшит и ввод фразой** — только после пилота с живыми пользователями.

## Что не проверено

- **Портал.** Макеты не открывались внутри Битрикс24. Ширины фреймов (1000–1400 px для полной версии, 400–800 px для вкладки задачи) взяты из постановки, а не замерены.
- **UI Kit.** Набор компонентов сверен по актуальной документации (context7, ветка `main`), а не по установленной версии 2.5.3 — `node_modules` в пространстве нет. Касается `B24NavigationMenu` с бейджами, вертикального меню, `B24CommandPalette`, `B24Slideover`.
- **Автовысота фрейма.** Как слайдер и закреплённый футер ведут себя в TASK_VIEW_TAB с автовысотой — предположение по коду (`requestIframeAutoHeight`, `useIframeResizeOnToggle`), на портале не проверено.
- **Лицензии.** Механизм проверки подписки в Маркетплейсе не прорабатывался. Состояния «не подключено / пробный / подключено» нарисованы, откуда брать статус — открытый вопрос.
- **Контраст.** Посчитан для ключевых пар (кнопки, основной и приглушённый текст), полный аудит не делался.
- **Оценки часов** — экспертные, по объёму страниц и компонентов в коде, без декомпозиции на задачи.

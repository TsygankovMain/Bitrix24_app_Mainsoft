# Demo Data Brief (Q1 2026)

## 1) Что это за приложение
Приложение для учета трудозатрат и управления бюджетом проектов в Bitrix24.
Ключевая логика:
1. Списания времени сотрудников (метки времени) привязываются к проекту.
2. По проекту считаются факт-часы, факт-стоимость, доходы/расходы и финрезультат.
3. Есть два типа проектов: `delivery` и `support`.

## 2) Сущности и связи

### A. Группа/проект в модуле задач (Workgroup/Project)
Это база для задач и для связи с PROJECT SPA.
Обязательные поля:
1. `NAME`
2. `PROJECT=Y`
3. `OWNER_ID`
4. `MEMBERS` (минимум 5 участников на группу)

Связь: `PROJECT.bitrix_group_id = workgroup.ID`.

### B. Проект (Smart Process: PROJECT)
Обязательные бизнес-поля:
1. `project_item_id` (ID элемента SPA, системный `id`)
2. `bitrix_group_id` (ID группы/проекта Bitrix)
3. `stage_id` (стадия)
4. `is_support` (bool)
5. `project_hours_budget` (часы, для delivery)
6. `hourly_rate` (ставка часа)
7. `curator_id` (пользователь)
8. `company_id` (компания)
9. `start_date`, `finish_date`
10. `is_archived` (bool)

Стадии (фиксированные):
1. `Новый`
2. `В просчете`
3. `В работе`
4. `Нет списаний 1 месяц`
5. `Нет списаний 3 месяца`
6. `Успех`
7. `Провал`

### C. Метка времени (Smart Process: TIMESHEET)
Обязательные поля:
1. `id_zadachi` (task_id)
2. `sotrudnik` (employee)
3. `kolichestvo_chasov` (hours)
4. `uchitivaem` (is_billable)
5. `opisanie` (comment)
6. `project_title`
7. `project_id` (bitrix_group_id)
8. `project_item_id` (ссылка на проект SPA)
9. `hourly_rate_snapshot` (снимок ставки на момент списания)
10. `data` (дата списания)

Связь: `timesheet.project_item_id = project.id`.

### D. Финоперация (Smart Process: FINANCE)
Обязательные поля:
1. `project_item_id` (ссылка на проект SPA)
2. `operation_type` (`income` | `expense`)
3. `amount`
4. `operation_date`
5. `source` (`deal_embed` | `manual`)

Дополнительно:
1. `deal_id` (обязательно для `deal_embed`)
2. `comment`
3. `responsible_user_id`
4. `currency` (`RUB`)

Связь: `finance.project_item_id = project.id`.

### E. Задача (Bitrix Tasks)
Нужно создать реальные задачи в рабочих группах проектов, чтобы метки времени ссылались на существующие `task_id`.
Базовые поля задачи:
1. `TITLE`
2. `DESCRIPTION`
3. `GROUP_ID` (равен `bitrix_group_id` проекта)
4. `RESPONSIBLE_ID`
5. `CREATED_BY`
6. `DEADLINE` (внутри Q1 2026)
7. `STATUS` (микс: новые/в работе/закрытые)

### F. Компании и сделки (для финансов)
Нужны для реалистичных операций `source=deal_embed`.
1. Компании: `crm.company`
2. Сделки: `crm.deal` (связаны с компаниями)
3. Для части финопераций использовать реальные `deal_id` созданных сделок

## 3) Требование к демоданным (строго)
Сгенерируй данные за период **2026-01-01 .. 2026-03-31**:
1. Группы/проекты в задачах: **10 шт**
2. Проекты в PROJECT SPA: **10 шт**
3. Метки времени: **200 шт** (допуск 190-210)
4. Финоперации: **40-60 шт**
5. Задачи: **70-100 шт**
6. Компании: **10 шт**
7. Сделки: **20-30 шт**

Распределение проектов:
1. `delivery`: 8 проектов
2. `support`: 2 проекта

Распределение по стадиям (примерно):
1. `Новый`: 1
2. `В просчете`: 1
3. `В работе`: 5
4. `Успех`: 2
5. `Провал`: 1

Правила генерации:
1. Для `delivery`: заполнить `project_hours_budget` (100-600), `hourly_rate` (1500-4500).
2. Для `support`: `is_support=true`, `project_hours_budget` пусто или 0, `hourly_rate` заполнен.
3. Каждая метка времени обязана иметь `project_item_id`, `project_id`, `hourly_rate_snapshot`.
4. `hourly_rate_snapshot` должен совпадать со ставкой проекта на дату списания.
5. `hours` в диапазоне 0.5-8.0, с шагом 0.5.
6. Не менее 15 сотрудников участвуют в списаниях.
7. Для каждого проекта минимум 12 меток времени за квартал (кроме 1 проекта-исключения с 0-2 метками для теста автостадий).
8. Для финопераций использовать оба типа `income` и `expense`; минимум 1 доход и 1 расход на каждый активный проект.
9. Для части операций ставить `source=deal_embed` и валидный `deal_id`; для остальных `source=manual`.
10. Каждая метка времени должна ссылаться на реально созданную задачу (`id_zadachi`).
11. Для каждой задачи создать от 1 до 5 меток времени (чтобы были повторные списания по одной задаче).
12. Поля иерархии в метках заполнять так:
    - `id_zadach_ierarhiya`: массив строк с `task_id` (минимум 1 элемент),
    - `title_zadach_ierarhiya`: массив названий тех же уровней.
13. У каждого PROJECT SPA элемента `bitrix_group_id` должен указывать на реально созданную группу из модуля задач.
14. Каждая задача должна быть создана внутри одной из 10 групп (`GROUP_ID` обязателен и валиден).
15. Минимум 50% финопераций делать со `source=deal_embed` и валидным `deal_id`; остальные — `manual`.

## 3.1) Порядок генерации (обязательный)
1. Создать 10 групп/проектов в модуле задач.
2. Создать 10 компаний.
3. Создать 20-30 сделок (привязать к компаниям).
4. Создать 10 элементов PROJECT SPA с корректным `bitrix_group_id`.
5. Создать 70-100 задач в этих группах.
6. Создать 200 меток TIMESHEET (с ссылками на существующие `task_id` и `project_item_id`).
7. Создать 40-60 FINANCE операций (часть с `deal_embed` + `deal_id`).

## 4) Что нужно получить на выходе
После загрузки данных в демо-портал должны выполняться условия:
1. В отчетах есть плотные данные за весь Q1 2026.
2. Есть проекты в разных бюджетных статусах (`Норма`, `Риск`, `Перерасход` и для support: `Плюс/Граница/Минус`).
3. Есть проверяемые кейсы:
   - проект с низкой загрузкой (для перехода в `Нет списаний ...`),
   - проект с перерасходом,
   - support-проект с отрицательным финрезультатом.
4. При выборке меток времени все `task_id` существуют в модуле задач.

## 5) Техническое примечание для webhook-скрипта
Создавай записи через REST Bitrix24 (`crm.item.add`) по трем SPA:
1. PROJECT SPA (`entityTypeId проекта`) — `crm.item.add`
2. TIMESHEET SPA (`entityTypeId трудозатрат`) — `crm.item.add`
3. FINANCE SPA (`entityTypeId финопераций`) — `crm.item.add`
4. Группы/проекты в задачах — `sonet_group.create`
5. Задачи — `tasks.task.add` (и при необходимости `tasks.task.update`)
6. Компании — `crm.company.add`
7. Сделки — `crm.deal.add`

Если коды пользовательских полей отличаются, сначала прочитай `crm.item.fields` для каждого `entityTypeId` и замапь поля по смыслу из этого брифа.

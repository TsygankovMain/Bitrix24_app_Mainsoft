# Смена секретных ключей после утечки из репозитория

## Почему это обязательно

Файл .env с ключами был случайно сохранён в истории git. Даже после удаления файла из репозитория, история git хранит все старые значения. Это означает, что любой, у кого была копия репозитория в момент утечки, мог увидеть все секретные ключи.

Поэтому нужно СМЕНИТЬ оба ключа, которые были открыты:
- CLIENT_SECRET приложения Bitrix24
- Токен CloudPub

Это единственный способ гарантировать, что скомпрометированные ключи больше не будут работать.

## Ключ 1: CLIENT_SECRET приложения Bitrix24

### Где взять новый ключ

1. Откройте портал Bitrix24
2. Перейдите в раздел **Разработчикам** (обычно в верхнем меню или боковой панели)
3. Найдите вашу установку приложения
4. Откройте **реквизиты приложения** (или similar section for app credentials)
5. Там будет текущий CLIENT_SECRET
6. Нажмите кнопку **пересоздать** или **обновить** секрет (обычно рядом со значением есть иконка обновления)
7. Новое значение скопируйте

### Куда вписать новый ключ

На сервере отредактируйте файл `.env`:

```
CLIENT_SECRET=ваше_новое_значение_из_битрикса
```

Убедитесь, что значение скопировано ровно, без пробелов в начале и конце.

## Ключ 2: Токен CloudPub

### Где взять новый токен

1. Откройте кабинет **CloudPub** (или сервис туннелирования, который вы используете)
2. Перейдите в раздел **Токены** или **API ключи**
3. Нажмите **Создать новый токен**
4. Скопируйте новый токен
5. Отозовите старый токен (обычно кнопка удаления или деактивации рядом с токеном)

### Куда вписать новый токен

На сервере отредактируйте файл `.env`:

```
CLOUDPUB_TOKEN=ваш_новый_токен_из_cloudpub
```

## Дополнительно: JWT_SECRET

Проверьте переменную `JWT_SECRET` в боевом файле `.env` на сервере.

**Если в `.env` стоит:**
```
JWT_SECRET=your_jwt_secret_key_here
```

То это заглушка — нужно сгенерировать случайную строку и вписать.

**Как сгенерировать:**
- Используйте любой генератор паролей (например, https://www.random.org/strings/)
- Или в терминале выполните:
  ```bash
  openssl rand -base64 64
  ```
- Скопируйте результат (строка должна быть 64+ символов)
- Вставьте в `.env`:
  ```
  JWT_SECRET=ваша_сгенерированная_строка
  ```

## Как применить новые ключи

1. Сохраните изменения в файле `.env` на сервере
2. Перезапустите приложение:
   - Если используете Docker: `docker compose restart`
   - Если запускали через `make`: `make down && make dev-python`
3. Подождите 10-20 секунд, пока приложение запустится
4. Откройте приложение в Bitrix24 (перезагрузите страницу браузера)
5. Проверьте, что вход работает

## Проверка

Приложение должно:
- Открываться без ошибок авторизации
- Загружать отчёты и данные корректно
- Отвечать на действия пользователя

**Если видите ошибку «ошибка авторизации» или «недоступно»:**
- Проверьте, что CLIENT_SECRET вписан без пробелов и кавычек
- Убедитесь, что выполнили `docker compose restart` (или перезапуск)
- Проверьте логи приложения (команда `make logs` или `docker compose logs`)

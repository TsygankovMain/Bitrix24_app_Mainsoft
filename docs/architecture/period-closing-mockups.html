ЭКРАН 7

Переоткрытие

Причина обязательна и попадает в журнал. Переоткрытие — событие, а не рутина: отчёт за месяц может измениться после того, как лёг в основу счёта.

Переоткрытие периода

Переоткрыть Июль 2026?

Записи периода снова станут доступны для изменения. Отчёт за июль может измениться — если он уже лёг в основу счёта, расхождение придётся объяснять.

Что проверяет проверка

Блокеры

Данные сломаны. Закрыть нельзя.

  • Записи без проектаНе попадут ни в один счёт, час потеряется
  • Задачи переехали, карточки не переписаныОтчёт разойдётся с положением задач
  • Записи без привязки к задачеНельзя ни проверить, ни объяснить клиенту

Предупреждения

Данные необычны. Закрыть можно.

  • Нулевые часыМусор, но на сумму не влияет
  • Сотрудник не списал ни часаБывает законно: отпуск, больничный
  • Больше 12 часов за деньБывает законно: аврал, выезд
  • Дубли по задаче, дате и часамБывает законно: два одинаковых куска работы

Разделение принципиальное. Если смешать одно с другим, люди приучатся нажимать «всё равно закрыть» — и проверка перестанет работать в тот момент, когда действительно понадобится.

Честная граница возможностей

Приложение не может физически запретить списание

Карточку часов можно создать и отредактировать в интерфейсе самого Битрикса, минуя приложение — там наш код просто не выполняется.

Запрет накрывает

  • Все экраны приложения: вкладка задачи, встроенный экран, отчёт по проекту
  • Любые попытки записи через наш API
  • Обход через устаревшую вкладку — её ловит защита версии сборки

Запрет не накрывает

  • Создание и правку карточки прямо в Битриксе
  • Изменения через бизнес-процессы и роботы портала

Физический запрет по-прежнему обеспечивают права Битрикса — так, как это делается сейчас. Закрытие в приложении даёт другое: замораживает цифры в отчётах, объясняет человеку причину отказа и делает опоздавшие часы видимыми.

Стыковка с тем, что уже работает

Три механизма, сделанных 31.08.2026, столкнутся с закрытием. Это надо решить до реализации, а не после.

Переписывание проекта при переносе задачи

Задача переехала — приложение переписывает проект во всех её карточках. Карточки закрытого периода трогать нельзя.

Решение. Пропускать их и показывать отдельной строкой «N карточек в закрытых периодах не изменены». Задача окажется разорванной: свежие часы в новом проекте, закрытые остались в старом. Так и должно быть — это зафиксированная история, а не ошибка.

Фоновое выравнивание расхождений

Ищет записи, чей проект разошёлся с текущей группой задачи, и правит их. С закрытыми периодами войдёт в бесконечный цикл: находит, пытается переписать, получает отказ прав Битрикса, повторяет через десять минут.

Решение. Исключить закрытые периоды из выборки на нашей стороне, а не упираться в отказ Битрикса.

Резолв проекта на чтении

Отчёт подставляет актуальный проект из справочника задач. Для закрытого периода это означало бы, что отчёт за июль меняется от переноса задачи в сентябре.

Решение. Для закрытых периодов резолв не применять — брать снимок из записи.

Открытые вопросы

  1. Часовой пояс

    Границы месяца считаются по времени портала. У Битрикса в профиле нет смещения, только строка зоны — считать придётся самим. Особенность известная, уже встречалась.

  2. Первое закрытие

    В базе данные с февраля 2026. Закрывать всё разом или начать с августа, оставив прошлое открытым навсегда?

  3. Кто закрывает

    Признак «администратор Битрикса» в приложении уже есть. Подойдёт ли он как «тот, кто закрывает месяц», или нужен отдельный список?
